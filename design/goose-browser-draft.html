Smooth, light, and on an engine we own

A private browser for the two of us: our own engine in Goose, with Rust for everything Goose lacks. It shows what each tab weighs, puts idle tabs to sleep, and opens a developer workbench with a project. This draft covers where the repo stands, what a browser weighs on your Mac, what the best browsers do in 2026, how our engine will work, and three directions for the interface.

The repo today

goose-mini-browser is a one-day learning demo. A window written in Goose scans a little HTML, and a small Rust library fetches pages over HTTP and HTTPS. The code is tidy and the README is honest about its limits. It proves Goose can open a window and fetch a page. For the engine we're building, nearly every part gets replaced: the scanner by a spec HTML parser, the Nuklear window by a Rust platform layer and GPU compositor, the fetch shim by a Rust network stack. The bugs below become the rules for that rebuild.

  1. Critical

    Any website can crash it

    A chunk-size line of ffffffffffffffff makes the Rust shim panic in dechunk (goosenet/src/lib.rs:166). The panic crosses the extern "C" boundary, and that aborts the whole browser.

    ReproducedA local server sent that one response; the calling process exited with code 134.

  2. Critical

    A link longer than 200 bytes crashes it

    Every URL lives in a u8[..200] buffer, and Goose aborts when a bounded array overflows. Long links are everyday: search results, tracking links, shop pages.

    Language docsGoose reference, section 5.3: exceeding the capacity aborts. Not run, because the Goose build was blocked.

  3. High

    Most real links go to the wrong address

    resolve() only joins a link to the current folder. On MDN, /en-US/docs/Web/CSS becomes …/docs//en-US/docs/Web/CSS; on https://example.com, about.html becomes the host about.html. Anchors, //cdn links and mailto: turn into page loads.

    Ran a portA line-for-line port of the function got five of seven common link types wrong.

  4. High

    Redirects lose the page's address

    The shim follows redirects but hands back only the status and body, so links on a redirected page resolve against the address you typed.

    Codegoosenet_fetch has no output for the final URL (lib.rs:29).

  5. High

    One dead link freezes navigation for 75 seconds

    All fetches share one worker and one queue, the connect has no timeout, and quitting waits for the worker.

    Measured75.0 s to an unreachable address, the macOS connect timeout.

  6. Medium

    Paragraphs are cut to one line

    Wrapped text sits in fixed 20-pixel rows, so a paragraph shows its first line only.

    ScreenshotVisible in the repo's own screenshot.png.

  7. Medium

    It redraws at the screen's refresh rate while idle

    gfx::frame() is a game loop with vsync, so an idle window keeps the CPU and GPU busy.

    Language docsGoose gfx reference. Not measured.

  8. Low

    Every HTTPS request rebuilds the TLS setup

    It reloads the whole root-certificate store per request and speaks HTTP/1.0 with no keep-alive, compression, cookies or cache.

    Codefetch_https and request_bytes in lib.rs.

Worth keeping

  • An honest README that lists what the demo does not do.
  • Fetches run off the UI thread, and stale results are dropped by request id.
  • The headless --frames N mode, a ready-made screenshot test.
  • rustls for TLS, with a body-size cap and read timeouts.

Setup

  • The README builds Goose from its main branch, which changed yesterday, and the language is two months old. Pin a commit.
  • Cargo.lock is ignored, so two builds can pull different crate versions.
  • No tests or CI, although the headless mode is ready for them.
  • The browser's header comment and both demo pages still say there is no networking.

Measured since: the demo builds and runs on your Mac. Left idle in a window it uses 13.8% CPU, redraws about 116 times a second, and holds 208–235 MB, about 175 MB of it GPU allocations.

What a browser weighs on your Mac

I built an 80 KB WebKit shell (a window with web views and nothing else) and ran it beside a fresh Chrome with a throwaway profile, on the same pages, twice. Memory is Activity Monitor's figure, with memory shared between processes counted once.

The page is the weight.GitHub's tab alone took 182.7–192.7 MB across three runs, about three times the whole bare WebKit shell with a blank tab.

Both engines pay the same for pages.Page processes took 266.6–266.8 MB in WebKit and 255.0–255.5 MB in Chrome, whose count includes a spare renderer.

The overhead is where they differ.Everything else took 66.8–81.7 MB for WebKit and 304.4–351.6 MB for Chrome. With one blank tab Chrome already sits at 389.7–428.5 MB.

These are the numbers our engine has to beat. Most of the weight is the pages, so ours must keep pages compact and put idle tabs to sleep.

MacBook Pro M5 Pro, 24 GB, macOS 26.5.1, 29 Oct 2026. Private sessions, 15 seconds to settle after loading, the last tab on screen. Chrome's figures include its spare renderer and, in the first run, its updater. Scripts and raw JSON: design/measurements/.

What the best browsers do

Two research passes on 29 Oct 2026. I checked every claim below against its source before using it.

  • Familiar first, power on request

    Arc's own numbers: “Only 5.52% of DAUs use more than one Space regularly.” Its makers called it too different, with too much to learn. Arc stops working on 22 Dec 2026.

    [1] [2]

  • Vertical tabs and split view are standard

    Chrome added native vertical tabs on 7 Apr 2026; Firefox 149 added Split View on 24 Mar 2026. Neither is a reason to switch anymore.

    [3] [4]

  • Sleep idle tabs

    Microsoft measured an 83% average memory saving for each sleeping tab in Edge. Our own numbers say the pages are most of the weight.

    [5]

  • Block ads inside the engine

    Google removed uBlock Origin from the Chrome Web Store in its last Manifest V2 purge. In our engine, blocking lives in the network layer, before a byte is parsed.

    [6]

  • Sync privately

    Apple encrypts Safari history, Tab Groups and iCloud Tabs end to end. A new browser should promise no less.

    [7]

  • Developers want every viewport in sync

    Polypane shows every breakpoint side by side, all synced; Sizzy mirrors devices in one workspace for $15 a month. Both are separate Chromium apps.

    [8] [9]

  • Build only what you can keep secure

    Kagi ended Orion for Linux and Windows on 2 Oct 2026 to focus on macOS and iOS; Arc's makers cited the constant work of keeping a browser secure. Our answer is scope: two users, Mac and iPhone, documents first, in two memory-safe languages.

    [10] [2]

The iPhone rule, and why it doesn't bind us

Outside the EU and Japan, every browser in the App Store runs Apple's WebKit. The EU (iOS 17.4 and later) and Japan (iOS 26.2 and later) allow other engines only in separate, region-only apps that pass 90% of the Web Platform Tests. In May 2026 Open Web Advocacy reported that no vendor had shipped one in the EU.

We aren't distributing, so we install our own engine on our own iPhones from Xcode. Two limits stay: apps can't JIT, so JavaScript runs interpreted, and iOS ends apps that use too much memory.

How our engine works

The full plan is in docs/ENGINE.md. In short: Goose owns the engine, Rust owns everything Goose lacks, and every frame is judged against 120 Hz. Apple silicon is the only target, so the engine leans on what it gives: one arm64 architecture, Metal, memory shared by CPU and GPU, and separate performance and efficiency cores.

  • Smooth first

    A frame is never late because of network, parsing or layout.

  • Memory is a budget

    Every part has a number, and the build fails when it goes over.

  • Idle means zero

    Nothing redraws, polls or runs while nothing changes.

  • One renderer

    The engine draws the pages and the browser's own interface.

  • Documents first

    Be the best at the pages we render before rendering more.

Dev mode

It turns on when you open a project: a local server, a folder, or a site you mark as yours. Owning the engine makes it better than an embedded engine allows.

  • Phone and desktop views of the same page, with scrolling and clicks mirrored between them.
  • Open on iPhone: the Mac shares your local server with your paired iPhone over Wi-Fi.
  • Every request with headers, bodies and timings, because the network stack is ours.
  • A frame strip that marks any frame over 8.3 ms and names what caused it.
  • The DOM, layout boxes and every tab's weight, live.

Three directions

One layout for all three, so the choice is about character. Each borrows four things from its world: type, colour, density and one signature move. The chrome will be HTML and CSS drawn by our own engine, so the winner becomes the first page the engine renders every day. Weights for Wikipedia, MDN, example.com and GitHub come from one measured run; the local site, the phone view and the iPhone figures are illustrative. Switch your system to dark mode to see each one at night.

A

Station

The calm of a Swiss railway: white, black, and red only for what is running.

Signature move

Stop-to-go. Every live tab carries a small second hand that sweeps and waits at the top of the minute, the way Swiss station clocks wait for the signal. A sleeping tab's hand stands still and its weight drops to 0 MB. When Mac and iPhone sync, every hand moves together.

Palette

  • Signal red#EB0000 · live tabs only
  • Departure yellow#FFDE00 · selection
  • Sign blue#1D2A6E · spaces
  • Clock black#0F0F0F · ink
  • Station white#FFFFFF · ground

Type

San Francisco throughout, with tabular figures set in a timetable's column rhythm.

Risk

Restraint can tip into austere, and the red only works while it stays rare. The SBB clock face is a licensed design, so we borrow its stop-to-go timing, never the face or its disc hand.

Taken from the worlds we turned down

  • Data field: exact megabytes with one decimal, never “high” or “low”
  • Orienteering map: red belongs to the live tab and nothing else
  • Botanical folio: every weight drawn at one fixed scale
  • Boarding pass: rows move in place, and a tab that changed while hidden keeps its mark until you look
  • Developer console: dev panels fold away by priority, and destructive actions stand apart
B

Terminal

Airport wayfinding for the web: one yellow band says where you are and where you can go next.

Signature move

The sign band. The toolbar is a yellow band with a black pictogram square for the kind of page, the destination in large type, and the next moves (iPhone, views, dev) locked to its edge. The tab you follow stays yellow from the sidebar to the band; everything else is black and white.

Palette

  • Signal yellow#FFCC00 · the band and the followed tab
  • Sign black#0B0B0B · panels
  • Panel frame#1A1A1A · sidebar
  • Surface grey#E6E6E6 · ground
  • Icon white#FFFFFF · pictograms

Type

Signika for destinations and figures; San Francisco for controls.

Risk

Yellow tires the eye if it spreads past the band and the followed tab. It is the boldest of the three for an everyday browser.

C

Pack

Built like ultralight gear: everything carries its weight, and the pack is always in view.

Signature move

The pack. The sidebar opens with the window's total and a bar split by tab at one fixed scale (500 MB across). Sleeping tabs leave the bar, turn glacier blue, and show what they save.

Palette

  • Safety orange#FF5A1F · live and primary
  • Glacier blue#0796B8 · asleep
  • Trail black#101418 · ink
  • Fabric white#F4F8F7 · translucent sidebar
  • Contour grey#C9D3D1 · wallpaper lines

Type

Archivo, semi-condensed, for labels; Martian Mono for weights; San Francisco for controls.

Risk

It sits closest to Arc's and Zen's sidebar, so it can read as familiar. The outdoor world has to stay in colour, type and the pack bar, never in textures.

My pick: it puts the product's promise, weight you can see, on every screen.

Worlds I weighed and turned down

  • Boarding pass and gate boardRead as a travel app. Station keeps its rows that move in place.
  • Developer consoleRead as a tool for developers only. Station keeps its folding panels.
  • Botanical folioToo far from a browser. Station keeps its single fixed scale.
  • Orienteering mapToo niche. Station keeps one colour for the live tab.
  • Data fieldToo cold for everyday use. Station keeps its exact figures.
